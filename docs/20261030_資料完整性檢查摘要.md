## 問題分類

| 等級 | 規則 | 項目數 |
|---|---|---:|
| warn | `missing-source` | 1862 |

`dangling-figure-event` 是人物連向不存在的事件；`dangling-event-figure` 是事件連向全域人物池中不存在的人物，均列失敗。來源缺漏、人物關係待複核與年代疑義列警告。不存在的關係對象也列警告，不能當作已確認歷史關係。

舊 `coords` 欄位使用現行正規化規則判讀，列格式警告；座標倒序才符合地理範圍時列 `coordinate-order-mismatch` 警告，未自行修正。生卒區間外事件可能涉及追贈、影響或資料錯連，需要逐筆人工複核。

未出現的失敗規則代表本次未發現：缺少／重複 ID、無效事件年份、無論何種座標順序都超出地理範圍。這不表示已查核地點是否符合史實。

## 可重跑命令

```powershell
npm run validate:data
node scripts/validate_history_data.mjs --json
node scripts/validate_history_data.mjs --strict
```

預設有失敗時退出碼為 `1`；沒有失敗時，警告仍會清楚列出、狀態為 `WARN`。加 `--strict` 後，若只有警告則退出碼為 `2`。`--json` 輸出完整逐項資料，本檢查器本身不寫入專案檔案。

## 介面失效連結防護

已靜態核對：

- `src/components/Timeline.js` 將事件人物 ID 解析成實際人物後使用 `.filter(Boolean)`，不渲染無效人物按鈕。
- `src/components/FigureModal.js` 解析參與事件後，找不到事件即 `return null`；關係卡只在找到實際人物時加入圖譜。
- `src/data/schemaNormalizer.js` 推薦關係產生時，找不到事件／人物即略過；保留原始 ID 供檢查，不擅自刪除資料。

上述防護避免顯示不存在對象的可點擊入口，**並未修復原始資料**；人物卡的原始事件／關係筆數仍可能包含失效參照。靜態程式檢查不等同已逐一點擊所有歷史連結。
