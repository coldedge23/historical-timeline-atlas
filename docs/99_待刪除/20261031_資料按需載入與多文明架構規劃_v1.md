## 一、結論摘要

1. **問題**：網站一開啟就下載全部文明、全部時期的資料。壓縮後總量 1,217 KB，已達上限的 81.1%。再加一個日本規模的文明（約 261 KB）就會超標，新增歐洲、中亞也一定會超標。
2. **建議**：改成「總目錄＋資料包」架構。一開始只下載程式和精簡的總目錄，切到哪個文明、哪個時期才下載那一包。人物、事件的跨時期連結改在建置時算好。
3. **附帶整理**：文明改成註冊制，新增文明時不用再到 `app.js` 加判斷。
4. **不變的部分**：網址格式、畫面、資料正本（`src/data/**/*.js`）、部署方式（GitHub Pages，不需後端）。
5. **做法**：分 5 個階段，每個階段都能單獨發布，也能單獨退回。建議在待辦 2 之前完成。

## 二、現況（2026-10-31 實測）

### 2.1 載入方式

- 建置：`build.cjs` 用 esbuild 打包，入口是 `src/main.js`，已開啟分包（`splitting`）。

## 三、目標架構

```text
建置時（npm run build）
  src/data/**/*.js（正本，不變）
        │ 正規化、建關係網、套用校正與政策、換算地圖座標
        ▼
  dist/data/catalog.json            總目錄（一開始就載入，力求精簡）
  dist/data/<文明>/<時期>.json        資料包（切換時才載入）

瀏覽器
  入口程式 ──▶ catalog.json ──▶ 目前時期的資料包
                                 └─ 切換時期時再抓下一包（看過的留在快取）
  地圖元件與底圖資料：切到該文明時才載入（維持現有的延後載入）
```

### 3.1 資料包

- 每個文明的每個時期各一包，內容是已經正規化、已經串好連結的事件、人物、戰役。
- 跨時期的連結在建置時就算好，連結本身記錄目標所在的文明與時期。點擊時才去載入目標資料包，不必事先下載全部資料。
- 臺灣頁引用的華夏人物（例如蔣中正），在建置時複製一份進臺灣資料包。
- 日本、臺灣事件的地圖座標在建置時換算好，資料包不再需要地圖邊界資料。
- 資料包是建置產物，跟 `dist/` 一樣不進版控。正本仍是 `src/data/**/*.js`，符合 `AGENTS.md`。

### 3.2 總目錄（catalog.json）

只放切換與搜尋需要的最小資訊：

| 內容 | 用途 |
|---|---|
| 文明清單、各時期名稱、年份範圍、事件／人物／戰役數量 | 選單、標頭數字 |
| 搜尋索引：ID、類型、名稱、字號、年份、所屬文明與時期 | 全站搜尋 |
| 同期對照索引：事件 ID、年份、標題、所屬文明與時期 | 同期東亞對照 |

總目錄會隨資料量成長，所以要單獨檢查大小（見 3.5）。

### 3.3 文明註冊制

```text
src/civilizations/
  registry.js                 文明清單（新增文明＝新增一行）
  china/config.js             名稱、預設時期、時期清單來源、陣營設定、地圖元件（延後載入）
  taiwan/config.js
  japan/config.js
```

- `navigation.js`、`Header.jsx`、`app.js` 改成讀取註冊清單，拿掉逐一判斷文明的程式碼。
- 臺灣、日本現有的「時期（era）」與華夏的「時期（period）」，在設定檔中統一描述，網址格式維持不變。

### 3.4 地圖

- 維持各文明各自的地圖元件，邊界資料跟著地圖元件延後載入。
- 共用世界底圖（多地區共用一套地理資料、各自設定範圍與投影）留到真正新增歐洲或中亞時再評估，這次不做。

### 3.5 體積檢查標準（需 Ivan 同意）

| 現行 | 建議 |
|---|---|
| 最大 JS ≤ 1,000 KB、JS＋CSS 總量 ≤ 1,500 KB | ① 首次載入（入口程式＋CSS＋總目錄＋預設時期資料包）≤ A KB<br>② 單一資料包 ≤ B KB<br>③ 總目錄 ≤ C KB |

- A、B、C 的數字待第 1 階段實測後提出，現在不預設。
- 這不是放寬，而是改成量使用者實際要等的下載量。依 `AGENTS.md`，修改檢查標準要 Ivan 同意，並同步更新 `AGENTS.md` 與 `README.md`。

## 四、分階段實施

每個階段都要通過 `npm run build`、`npm test`、`npm run verify`、`node scripts/validate_history_data.mjs --effective`，並在瀏覽器實測後才 commit、push。

| 階段 | 內容 | 畫面變化 | 風險 |
|---|---|---|---|
| 0. 建立比對基準 | 新增測試，把現行的搜尋結果、同期對照、跨時期連結、網址導覽結果存成基準，供後續階段比對 | 無 | 低 |
| 1. 建置時產生資料包 | 新增建置步驟，產出 `catalog.json` 與各資料包；前端暫不使用。測試比對資料包內容與現行執行時的結果一致，並實測各包大小，提出 3.5 的 A、B、C | 無 | 低 |
| 2. 華夏改讀資料包 | 前端新增資料載入層（下載、快取、載入中狀態）；華夏各時期、全站搜尋、同期對照改用總目錄與資料包 | 切到沒看過的時期時，短暫顯示載入中 | **高**：改動最大，跨時期連結與搜尋要逐項比對階段 0 的基準 |
| 3. 臺灣、日本改讀資料包＋文明註冊制 | 臺灣、日本改用資料包；建立 `src/civilizations/`，拿掉散落各處的文明判斷 | 同上 | 中 |
| 4. 檢查標準與文件 | 改用新的體積檢查（經 Ivan 同意），更新 `AGENTS.md`、`README.md`、交接手冊；新增「如何新增一個文明」說明 | 無 | 低 |

- 每個階段至少一個 commit，出問題時可以只退回那一個階段。
- 第 2 階段完成前，可以先暫停待辦 2；也可以第 1 階段完成、確認資料包架構可行後，就先做待辦 2，由第 2 階段承接資料增加的部分。

## 五、相容性

| 項目 | 影響 |
|---|---|
| 網址 | 維持 `#period=…`、`#civ=japan&era=…`、`event`、`figure`、`battle` 等參數，舊的分享連結照常可用 |
| 部署 | 仍由 GitHub Actions 建置發布到 GitHub Pages；資料包是靜態 JSON，不需後端 |
| 資料編修方式 | 不變，仍改 `src/data/**/*.js`；資料包每次建置自動重新產生 |
| 現有稽核腳本 | `validate_history_data.mjs` 仍讀正本，不受影響 |
| 本機預覽 | `npm run preview` 照常使用；不能直接用檔案方式開啟 `dist/index.html`（現在也不行） |

## 六、風險與驗證

| 風險 | 對策 |
|---|---|
| 跨時期連結、連結校正結果遺失或改變 | 階段 0 的基準測試逐筆比對；人物頁「參戰會戰紀錄」等跨資料集項目列入瀏覽器實測 |
| 搜尋結果改變 | 以相同關鍵字比對新舊結果 |
| 切換時期變慢 | 顯示載入中；看過的資料包留在快取；必要時預先下載相鄰時期 |
| 手機網路不穩，資料包下載失敗 | 顯示錯誤與重試按鈕，不能只留空白畫面 |
| 總目錄隨資料成長變大 | 單獨設上限；必要時把搜尋索引再按文明拆開 |

瀏覽器實測清單（每個階段）：電腦與手機寬度；華夏、臺灣、日本各切換數個時期；直接開啟帶 `event`、`figure`、`battle` 參數的網址；全站搜尋；同期對照跳轉；人物誌、戰役錄；劇院滿版地圖。
