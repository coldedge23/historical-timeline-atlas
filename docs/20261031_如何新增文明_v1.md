# 歷史星圖：如何新增一個文明 v1

| 項目 | 內容 |
|---|---|
| 日期 | 2026-10-31 |
| 版本 | v1 |
| 依據 | 階段 3 文明註冊制（`src/civilizations/`）與階段 4 的現行程式；規劃文件 `docs/20261031_資料按需載入與多文明架構規劃_v2.md` 第 3.7 節 |
| 適用 | 新增與華夏、臺灣、日本並列的文明（例如歐洲、中亞）。在既有文明內新增時期或資料，不需要照這份文件 |

---

## 一、結論摘要

1. 瀏覽器端只要新增一個資料夾 `src/civilizations/<文明>/config.js` 和一個地圖元件，再到 `registry.js` 登記一行。選單、網址、同期對照、徽章都從註冊清單讀取，不用改 `app.js` 或其他元件。
2. 建置端目前仍要**逐檔手動接上**新文明的資料（第四節列出 5 個檔案），這部分還沒有做成註冊制。
3. 新增文明會讓搜尋、同期對照等比對基準合理地改變，基準檔不得自行重新產生，要先請 Ivan 決定（第六節）。
4. 完成後必須通過 5 項檢查與 5 項體積上限；超過上限時要先瘦身或拆分，不調高上限。

---

## 二、先決定兩件事

| 決定 | 選項 | 影響 |
|---|---|---|
| 顯示單位 `unit` | `'period'`：每個時期一個資料包（華夏）<br>`'era'`：整個文明一個資料包，用紀元切換（臺灣、日本） | 決定網址格式（`#period=…` 或 `#civ=<id>&era=…`）與資料包切法。整包的壓縮後大小不得超過 600 KB（B） |
| 共用世界底圖 | 規劃 v2 已核准延後，到實際新增歐洲、中亞時再評估 | 目前每個文明各自有地圖元件 |

---

## 三、瀏覽器端（`src/`）

### 3.1 新增 `src/civilizations/<id>/config.js`

照 `japan/config.js`（`unit: 'era'`）或 `china/config.js`（`unit: 'period'`）的格式。欄位：

| 欄位 | 說明 |
|---|---|
| `id` | 文明代號，也是網址 `civ=` 的值與資料夾名稱（首次載入檢查依資料夾找設定檔） |
| `name`、`shortName` | 選單全名與同期對照、總目錄用的簡稱 |
| `unit` | `'period'` 或 `'era'` |
| `pageId` | `unit: 'era'` 時，該文明唯一資料包的代號 |
| `pageIdFor(periodId)` | `unit: 'period'` 時，時期對應的資料包代號 |
| `defaultPeriodId`／`defaultEraId` | 切到這個文明時預設顯示的時期或紀元，必須存在於建置出的總目錄 |
| `figureIdPrefix` | 該文明人物 ID 的前綴（`unit: 'era'` 用於判斷人物屬於哪個文明） |
| `eraLandingEvent(events, era)` | `unit: 'era'` 時，選紀元後要選取的事件 |
| `battleRefocusesSameEra` | `unit: 'era'` 時，在同一紀元點戰役是否把年表移到紀元第一個事件（臺灣 `false`、日本 `true`） |
| `loadMap` | 只能寫成 `() => import('../../components/<名稱>Map.jsx').then(m => m.<元件>)` |
| `features.demographics` | 是否顯示人口統計 |
| `badgeClass` | 年表徽章的樣式 |
| `regimeLabel(year)` | 同期對照時，該年份在這個文明顯示的政權或時代名稱 |

設定檔的限制（`tests/civilizations.test.js` 會檢查）：

- 不可有任何靜態 `import`，不可引用 `src/data/`。
- 地圖元件只能用上面那種動態 `import()` 載入，才不會進入主程式。

### 3.2 在 `src/civilizations/registry.js` 登記

- 在檔案開頭加一行 `import <id> from './<id>/config.js';`，並加入 `CIVILIZATIONS` 陣列。
- 陣列順序就是文明選單與同期對照的順序。

### 3.3 地圖元件 `src/components/<名稱>AtlasMap.jsx`

- 取歷史資料一律經 `src/store/historyStore.js`，不可直接 import `src/data/` 的歷史內容。
- 地理資料（邊界、座標）可以直接引入，但只能出現在延後載入的地圖分包（`tests/bundle-boundary.test.js`）。新的引入要登記在 `tests/history-store.test.js` 的 `KNOWN_DIRECT_DATA_IMPORTS`。
- 地圖分包會計入首次載入（A）。日本地圖含邊界資料約 95 KB，可作為參考。

### 3.4 不要做的事

- 不要在程式裡寫 `'<id>' === …` 這類判斷，改用設定的能力（`unit`、`features` 等）。除了 `src/civilizations/` 與 `src/data/`，`src/` 裡出現文明代號字串會讓測試失敗。

## 四、資料與建置端

### 4.1 資料正本

- 放在 `src/data/<id>/`，格式比照 `src/data/japan/`（`events`、`figures`、`battles`、紀元或時期設定）。
- 每個新的 `.js` 檔都要登記在 `scripts/data_file_classes.json`：歷史內容放 `content`、地理資料放 `geo`、小型設定放 `config`。未登記會讓 `tests/data-boundary.test.js` 失敗。
- 依 `AGENTS.md` 資料誠信規則：不編造年代、人物、兵力、來源；不確定的值標「待考」或「待確認」。

### 4.2 目前要手動接上的建置檔案

| 檔案 | 要加的內容 |
|---|---|
| `src/data/linkedHistoryCatalog.js` | 把新文明的資料集加入 `buildHistoryLinkGraph` 的輸入，並匯出該文明的事件、人物清單 |
| `src/data/historyLinkGraph.js` | 第 5 行依資料集代號判斷文明，加入新資料集代號（或讓資料集自帶 `civ` 欄位） |
| `scripts/lib/app_views.mjs` | `PAGE_IDS`、`buildPage`、`navigationCatalogs`、`contemporaryPools`、`APP_ERAS`、`APP_INITIAL_CONTEXT`、`APP_SELECTION_CONTEXT` 各加一個分支 |
| `scripts/build_data_packs.mjs` | `buildPack` 加入該文明的資料包欄位（紀元、`eraBattleIds` 等）；總目錄 `eras` 加入新文明的紀元選單 |
| `scripts/validate_history_data.mjs` | 把新資料集加入稽核清單，並確認座標順序規則（`[lng,lat]` 或 `[lat,lng]`） |

這些檔案位於 `scripts/` 或 `src/data/`，可以寫文明代號。日後若改成註冊制，需另列計畫。

## 五、檢查

每次修改後都要跑（全部通過才可 commit；push 前先問 Ivan）：

```powershell
npm run build
npm test
npm run verify
node scripts/validate_history_data.mjs --effective
npm run validate:data
```

- `validate:data` 現況就有 174 項既有失敗；比對清單，不得新增非預期項目。
- `npm run verify` 會檢查 5 項體積上限（壓縮後）：首次載入 800 KB、最大資料包 600 KB、總目錄 60 KB、搜尋索引 650 KB、程式與資料總量 3,200 KB（依據 `docs/20261031_資料包體積實測_v4.md`）。新增文明會增加總目錄、搜尋索引與總量。
- 瀏覽器實測：冷啟動深層連結、切換文明與紀元、搜尋、跨資料包連結、同期對照、返回鍵、手機寬度。新增文明後，也要依體積實測 v3 第 2.2 節用瀏覽器重新核對一次首次載入的檔案清單。

## 六、比對基準（需 Ivan 決定）

- `tests/fixtures/baseline/` 是階段 0 存下的行為基準，原則上不重新產生。
- 新增文明的資料會讓搜尋結果、同期對照、各頁數量合理地改變，`tests/baseline.test.js`、`tests/data-packs.test.js`、`tests/history-store.test.js` 會因此失敗。
- 處理方式：**待確認**。建議做法是先提出差異清單（哪些搜尋詞、哪些同期對照改變），經 Ivan 確認只有新文明造成的預期差異後，再執行 `node scripts/capture_baseline.mjs` 重新產生基準，並在 commit 說明記錄。
