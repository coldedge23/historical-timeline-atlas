| 項目 | 內容 |
|---|---|
| 日期 | 2026-11-08 |
| 版本 | v2；v1 移至 `docs/99_待刪除/` |
| v2 修改原因 | 依第一個新增的文明「二戰歐洲戰場」（`europewar`，規劃 `docs/20261108_二戰歐洲戰場模組規劃_v7.md`）的實作改寫：補上專題範圍 `scope`、命名限制、座標順序宣告、本次多改的檔案、比對基準的實際做法 |

## 一、結論摘要

1. 瀏覽器端：新增 `src/civilizations/<id>/config.js` 和一個地圖元件，再到 `registry.js` 登記一行。選單、網址、同期對照、徽章都從註冊清單讀取。
2. 只涵蓋一段年份的專題，設定檔要加 `scope`，否則任何年代的事件都會出現這個文明的同期對照列（第二節）。
3. 命名有測試限制：資料夾全小寫英文字母、資料包代號與地圖元件檔名只能用英文字母（2.2）。
4. 建置端仍要**逐檔手動接上**新文明的資料（4.2 列出 4 個要改的檔案）。新文明的資料格式超出舊文明時，還會多改不少檔案；二戰歐洲連同資料正本共改了 42 個程式、資料與測試檔（4.3）。
5. 新增文明一定會改變比對基準。先輸出到暫存資料夾比對差異，經 Ivan 確認後才覆蓋基準（第六節）。
6. 完成後必須通過 5 項檢查與 5 項體積上限；超過上限時要先瘦身或拆分，不調高上限。

## 二、先決定的事

### 2.1 文明的型態

| 決定 | 選項 | 影響 |
|---|---|---|
| 顯示單位 `unit` | `'period'`：每個時期一個資料包（華夏）<br>`'era'`：整個文明一個資料包，用紀元切換（臺灣、日本、二戰歐洲） | 決定網址格式（`#period=…` 或 `#civ=<id>&era=…`）與資料包切法。整包的壓縮後大小不得超過 600 KB（B） |
| 長時段或專題 | 長時段：不設 `scope`<br>專題：`scope: { kind: 'topic', yearRange: [起年, 迄年] }` | 專題只對範圍內年份的事件顯示同期對照列；本身的事件也只對照其他文明範圍內的事件。由 `registry.js` 的 `civCoversYear` 判斷，建置與瀏覽器共用 |
| 座標順序 | `'lngLat'`（臺灣、日本、二戰歐洲）或 `'latLng'`（華夏，也是沒宣告時的預設） | 宣告在資料集設定（`src/data/<id>/` 匯出、`linkedHistoryCatalog.js` 與 `validate_history_data.mjs` 讀取），不放文明設定 |
| 共用世界底圖 | 規劃 v2 已核准延後 | 目前每個文明各自有地圖元件 |

### 2.2 命名限制（測試會擋）

| 項目 | 規則 | 檢查的測試 | 二戰歐洲的例子 |
|---|---|---|---|
| 文明代號、資料夾名稱 | 全小寫英文字母 | `tests/civilizations.test.js` | `europewar`（`ww2Europe` 會失敗） |
| 地圖元件檔名 | 只能英文字母 | `tests/civilizations.test.js` | `EuropeWarAtlasMap.jsx` |
| 資料包代號 `pageId` | 只能英文字母 | `tests/data-packs.test.js` | `europeWarAtlas` |
| 人物 ID 前綴 `figureIdPrefix` | 該文明人物共用，用來判斷人物屬於哪個文明 | — | `fig_ew_` |
| 紀元 ID | 不得和其他文明重複 | — | `ewar_blitz` 等 4 個 |
| 人物、指揮官的中文名稱 | 不要包含其他文明人物的全名。人物連結用名稱子字串比對（`src/utils/relationRules.js`），例如「李斯特」會連到秦朝的李斯 | 基準比對 `figureLinks` | 巴爾幹戰役的 List 寫成「利斯特」 |

## 三、瀏覽器端（`src/`）

### 3.1 新增 `src/civilizations/<id>/config.js`

照 `europewar/config.js`、`japan/config.js`（`unit: 'era'`）或 `china/config.js`（`unit: 'period'`）的格式。欄位：

| 欄位 | 說明 |
|---|---|
| `id` | 文明代號，也是網址 `civ=` 的值與資料夾名稱（首次載入檢查依資料夾找設定檔） |
| `name`、`shortName` | 選單全名與同期對照、總目錄用的簡稱 |
| `unit` | `'period'` 或 `'era'` |
| `pageId` | `unit: 'era'` 時，該文明唯一資料包的代號 |
| `pageIdFor(periodId)` | `unit: 'period'` 時，時期對應的資料包代號 |
| `defaultPeriodId`／`defaultEraId` | 切到這個文明時預設顯示的時期或紀元，必須存在於建置出的總目錄 |
| `figureIdPrefix` | 該文明人物 ID 的前綴 |
| `scope` | 專題才設：`{ kind: 'topic', yearRange: [起年, 迄年] }`（2.1） |
| `eraLandingEvent(events, era)` | `unit: 'era'` 時，選紀元後要選取的事件 |
| `loadMap` | 只能寫成 `() => import('../../components/<名稱>Map.jsx').then(m => m.<元件>)` |
| `features.demographics` | 是否顯示人口統計 |
| `badgeClass` | 年表徽章的樣式 |
| `regimeLabel(year)` | 同期對照時，該年份在這個文明顯示的名稱。專題在範圍外回傳空字串 |

設定檔的限制（`tests/civilizations.test.js` 會檢查）：

- 不可有任何靜態 `import`，不可引用 `src/data/`。
- 地圖元件只能用上面那種動態 `import()` 載入，才不會進入主程式。

### 3.2 在 `src/civilizations/registry.js` 登記

- 在檔案開頭加一行 `import <id> from './<id>/config.js';`，並加入 `CIVILIZATIONS` 陣列。
- 陣列順序就是文明選單與同期對照的順序（二戰歐洲排在日本之後）。

### 3.3 地圖元件 `src/components/<名稱>AtlasMap.jsx`

- 取歷史資料一律經 `src/store/historyStore.js`，不可直接 import `src/data/` 的歷史內容。
- 地理資料（海岸線、邊界、城市點位）可以直接引入，但只能出現在延後載入的地圖分包（`tests/bundle-boundary.test.js`）。每個新的引入都要登記在 `tests/history-store.test.js` 的 `KNOWN_DIRECT_DATA_IMPORTS`。
- 地圖分包會計入首次載入（A）。日本地圖含邊界資料約 95 KB；二戰歐洲只畫海岸線與 15 個城市標籤，約 18.7 KB（壓縮後）。
- 二戰歐洲的底圖由 `scripts/build_europewar_basemap.mjs` 從 Natural Earth 產生，記錄版本與 SHA-256，下載檔不進 git，可作為新地圖的範本。

### 3.4 不要做的事

- 不要在程式裡寫 `'<id>' === …` 這類判斷，改用設定的能力（`unit`、`scope`、`features` 等）。除了 `src/civilizations/` 與 `src/data/`，`src/` 裡出現文明代號字串會讓測試失敗。
- 不要把元件裡寫死各資料包的設定再加一個分支。二戰歐洲把戰役錄分段搬到 `src/data/battlePhases.js`（`config` 類），依資料包代號查表。

## 四、資料與建置端

### 4.1 資料正本

- 放在 `src/data/<id>/`，格式比照 `src/data/europewar/` 或 `src/data/japan/`（`events`、`figures`、`battles`、紀元設定、`index.js` 匯出）。
- 每個新的 `.js` 檔都要登記在 `scripts/data_file_classes.json`：歷史內容放 `content`、地理資料放 `geo`、小型設定放 `config`。未登記會讓 `tests/data-boundary.test.js` 失敗。
- 資料集要明確帶 `civ: '<id>'`。沒有 `civ` 的資料集，`src/data/historyLinkGraph.js` 會判成華夏。
- 依 `AGENTS.md` 資料誠信規則：不編造年代、人物、兵力、來源；不確定的值標「待考」或「待確認」。
- 人物不要讓程式代填娛樂性評分與籍貫：二戰歐洲人物寫 `abilities: null`（`schemaNormalizer.js` 遇到 `null` 不算分，人物彈窗不顯示雷達圖），並填 `nativePlaceAncient`，否則籍貫會顯示預設值「華夏九州」。

### 4.2 要手動接上的建置檔案

| 檔案 | 要加的內容 |
|---|---|
| `src/data/linkedHistoryCatalog.js` | 新資料集（含 `civ`、`coordinateOrder`）加入 `buildHistoryLinkGraph` 的輸入，並匯出 `LINKED_<ID>_EVENTS`、`_FIGURES`、`_BATTLES` |
| `scripts/lib/app_views.mjs` | `PAGE_IDS`、`buildPage`、`navigationCatalogs`、`contemporaryPools`、`APP_ERAS`、`APP_INITIAL_CONTEXT`、`APP_SELECTION_CONTEXT` 各加一個分支 |
| `scripts/build_data_packs.mjs` | `buildPack` 加入該文明的資料包欄位（紀元、`eraBattleIds` 等）；總目錄 `eras` 加入新文明的紀元選單 |
| `scripts/validate_history_data.mjs` | 新資料集加入稽核清單並宣告 `coordinateOrder`；要做結構化來源檢查時，在 `STRICT_RULES` 登記 |
| `src/data/historyLinkGraph.js` | 資料集有帶 `civ` 時**不用改**（v1 寫要改第 5 行，已不需要） |

這些檔案位於 `scripts/` 或 `src/data/`，可以寫文明代號。`scripts/capture_baseline.mjs` 已改讀註冊表，新增 `unit: 'era'` 的文明不用再改。

### 4.3 二戰歐洲另外改的檔案

二戰歐洲的戰役與事件格式比舊文明多（起訖日期、規模、作戰型態、戰場、參與方、相關戰役、結構化來源），所以除了 4.2 還改了下列檔案。新文明只沿用舊格式時不用改；要用到同樣的欄位時，這些地方已經可以共用。

| 檔案 | 修改 |
|---|---|
| `src/civilizations/registry.js` | `civCoversYear`（專題範圍）、`ERA_CIVS` |
| `src/utils/relationRules.js` | 同期對照依 `civCoversYear` 過濾 |
| `src/components/Timeline.js` | 同期對照標題由「同期東亞歷史橫向對照」改為「同期歷史對照」 |
| `src/data/factionConfig.js` | 新資料包的陣營名稱與樣式 |
| `src/data/battlePhases.js`、`src/components/BattlesView.js` | 戰役錄分段從元件搬到設定檔；分段與篩選 |
| `src/components/BattleModal.js`、`src/app.js` | 起訖日期、規模、作戰型態、戰場、參與方、代表位置；相關戰役連結與切換（返回鍵回到前一場） |
| `src/utils/linkDerivation.js`、`src/store/historyStore.js` | 相關戰役的連結描述 |
| `src/utils/battleFilters.js`、`src/utils/datedRecords.js` | 戰役分類篩選；日期格式與依日期歸入紀元 |
| `src/utils/conicProjection.js` | 地圖投影（建置腳本、地圖、測試共用） |
| `src/utils/search.js` | 搜尋也比對戰役參與方（`participants`）的名稱 |
| `src/store/packSource.js` | 紀元選單改依註冊表的 `ERA_CIVS` |
| `src/data/schemaNormalizer.js`、`src/components/FigureModal.js` | `abilities: null` 不算分、不顯示雷達圖 |
| `src/types/history.ts` | 新欄位與座標順序的型別說明 |
| `scripts/lib/strict_rules.mjs` | 結構化來源檢查：已填的欄位必須有來源的 `claims` 支持；日期、地圖範圍、相關戰役雙向 |
| `scripts/capture_baseline.mjs` | 改讀註冊表；新增 `--out <資料夾>` |
| 測試 | `tests/europewar.test.js`、`tests/europewar-map.test.js`（錨點與座標顛倒、城市標籤、地圖範圍）；`civilizations`、`data-packs`、`history-store` 測試的清單 |

## 五、檢查

每次修改後都要跑（全部通過才可 commit；push 前先問 Ivan）：

```powershell
npm run build
npm test
npm run verify
node scripts/validate_history_data.mjs --effective
npm run validate:data
```

- `validate:data` 現況就有 174 項既有失敗、4,672 項警告；比對清單，不得新增非預期項目。
- `npm run verify` 檢查 5 項體積上限（壓縮後）：首次載入 800 KB、最大資料包 600 KB、總目錄 60 KB、搜尋索引 650 KB、程式與資料總量 3,200 KB（依據 `docs/20261031_資料包體積實測_v4.md`）。新增二戰歐洲後總目錄 35 KB、搜尋索引 484 KB、總量 2,524 KB（2026-11-08）。
- 瀏覽器實測：冷啟動深層連結、切換文明與紀元、搜尋、跨資料包連結、同期對照、返回鍵、手機寬度。實測完關掉預覽伺服器，確認 8080 埠已釋放。

## 六、比對基準

- `tests/fixtures/baseline/` 是階段 0 存下的行為基準。新增文明一定會讓搜尋、同期對照、各頁數量改變，`tests/baseline.test.js`、`tests/data-packs.test.js`、`tests/history-store.test.js` 會失敗。
- 做法（二戰歐洲實際採用）：
  1. `node scripts/capture_baseline.mjs --out <暫存資料夾>` 先輸出到別處。
  2. 和 `tests/fixtures/baseline/` 逐檔比對，列出差異種類。
  3. 交給 Ivan 確認差異都是預期的，才執行 `node scripts/capture_baseline.mjs` 覆蓋基準，並在 commit 說明記錄。
  4. `validateFailures.json` 重產後常常只有換行符號不同，這種情況用 `git checkout --` 還原。
- Ivan 可以預先授權特定種類的差異。二戰歐洲階段 4 的授權範圍（2026-11-07）：本模組新增的紀錄、其他文明事件多出的二戰歐洲同期對照列、新戰役名稱把其他頁較舊的搜尋結果擠出 24 筆上限。其他種類的差異（例如舊文明的人物連結改變）一律先停下來問。
